# Полное руководство по CIDR Scanner

Консольная проверка отдельных IPv4-адресов из списка CIDR через ICMP или TCP. Результат относится к конкретному проверенному IP: успешная проверка одного адреса не помечает всю подсеть рабочей.

Переработанная версия [munstr001/cidrs-roller](https://github.com/munstr001/cidrs-roller), исходный коммит `d3bd031`. Исходный файл запуска `real-check-avaibility.py` сохранён; основная логика находится в `cidr_scanner.py`, сетевые проверки — в `cidr_probes.py`, хранение результатов — в `cidr_journal.py`, прогресс и оценка времени — в `scan_progress.py`. Программа использует стандартную библиотеку Python и не обращается к API хостингов или Telegram.

## Требования

- Python 3.10 или новее.
- Для ICMP — установленная системная команда `ping`, доступная через `PATH`. На Windows она обычно уже есть.
- Для TCP внешние программы не нужны. Устанавливать пакеты через `pip` не требуется.

## Запуск

Из папки проекта:

```powershell
python real-check-avaibility.py --help
python real-check-avaibility.py --input my-cidrs.txt --source-label my-network
```

Файл `my-cidrs.txt` нужно подготовить самостоятельно. Одна строка — IPv4 CIDR либо отдельный IPv4. Допускаются пустые строки и комментарии после `#`:

```text
203.0.113.0/24
198.51.100.42/32
192.0.2.10
```

Это адреса для примера формата; замените их адресами своей проверки. Если `--input` не задан, используется поставляемый `cidrs.txt` рядом со скриптом. Он содержит 11 482 IPv4-подсети RU из снимка IPdeny от 4 ноября 2026 года. Относительный путь, переданный через `--input`, определяется текущим рабочим каталогом; путь по умолчанию не зависит от папки запуска.

Пример TCP-проверки порта 443:

```powershell
python real-check-avaibility.py --input my-cidrs.txt --protocol tcp --port 443 --timeout 2 --attempts 3 --workers 8 --rate 10 --source-label home-network
```

Полный набор параметров:

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `--input FILE` | `cidrs.txt` рядом со скриптом | Файл IPv4 и CIDR |
| `--output-dir DIR` | Новая папка в `results/` рядом со скриптом | Каталог нового запуска |
| `--resume DIR` | Не задан | Продолжить запуск из существующего каталога |
| `--protocol icmp\|tcp` | `icmp` | Способ проверки |
| `--port N` | `443` | Порт TCP |
| `--timeout SECONDS` | `1` | Время ожидания одной сетевой попытки, больше 0 и не более 60 секунд |
| `--attempts N` | `2` | Максимальное число попыток на IP, от 1 до 10 |
| `--samples N` | `3` | Число адресов, выбираемых из каждой подсети, от 1 до 256 |
| `--workers N` | `16` | Число одновременно работающих проверок, от 1 до 256 |
| `--rate N` | `20` | Максимальная частота начала сетевых попыток в секунду |
| `--source-label TEXT` | `unspecified` | Ваша подпись источника измерения |

Параметры `--output-dir` и `--resume` используются по отдельности. Без них создаётся каталог с текущим временем и уникальным суффиксом. Существующий каталог нового запуска не перезаписывается.

## Прогресс и время выполнения

Прогресс включён автоматически. Во время работы программа примерно раз в две секунды показывает:

- число обработанных IP-проверок и общее количество;
- процент выполнения;
- прошедшее время текущего запуска;
- примерное оставшееся время;
- фактическую скорость обработки IP в секунду.

Общее количество соответствует выбранным образцам, а не всем адресам подсетей. При обычном запуске поставляемого списка это 34 446 IP-проверок: 11 482 сети по три адреса. Повторные попытки одного IP не увеличивают счётчик обработанных адресов.

Оставшееся время вычисляется по фактической средней скорости текущего запуска. До первых трёх завершённых проверок и хотя бы одной секунды работы отображается «расчёт…». Оценка уточняется при изменении скорости, ответов и тайм-аутов; это приблизительное время.

При `--resume` ранее завершённые проверки сразу учитываются в проценте, а скорость и оставшееся время рассчитываются только по новой работе. После завершения показывается фактическая длительность; при остановке сохраняются текущие показатели без ложных 100%.

В терминале строка прогресса обновляется на месте, а при перенаправлении вывода в файл записываются обычные строки. Новых параметров запуска или библиотек устанавливать не нужно.

Пример строки после накопления измерений:

```text
[Прогресс] Обработано: 1200/34446 (3.5%) | Прошло: 00:02:00 | Осталось: ~00:55:25 | Скорость: 10.00 IP/с
```

Если скрипт уже запущен, новый индикатор появится после перезапуска. Можно остановить текущий процесс через `Ctrl+C` и продолжить его через `--resume`, сохранив готовые результаты.

## Как выбираются адреса

По умолчанию выбираются до трёх хостовых адресов: первый, средний и последний. Выбор детерминированный, без перечисления всех адресов большой сети. Если доступных адресов меньше, проверяется каждый из них один раз. Отдельный IPv4 и `/32` дают один адрес; `/31` — два.

Параметр `--samples 1` оставляет только первый хостовый адрес. Повторы исходных сетей нормализуются и удаляются. IPv6 не поддерживается; неверные строки учитываются как ошибки входных данных.

Успех одного образца означает доступность только этого образца. Даже несколько положительных проверок не подтверждают все IP диапазона.

## Результаты

Каждый запуск записывает в свой каталог:

- `results.jsonl` — результаты по конкретным IP: исходный CIDR, адрес, протокол, порт, статус, причина, число попыток, время и подпись источника.
- `reachable-cidrs.txt` — уникальные исходные CIDR, в которых хотя бы один выбранный IP дал успешный ответ хотя бы один раз. Одна подсеть на строку; маска исходного диапазона сохраняется, соседние сети не объединяются. Для отдельного IP используется `/32`. Это список кандидатов, а не подтверждение доступности каждого IP подсети.
- `errors.jsonl` — ошибки входных данных и выполнения проверок.
- `manifest.json` — параметры и идентификатор входных данных для продолжения запуска.

Служебный файл `.scan.lock` предотвращает одновременную запись двух процессов в один каталог. Блокировка освобождается операционной системой при завершении процесса, в том числе аварийном; наличие самого файла не мешает продолжению.

CIDR добавляется в TXT сразу при первом успешном образце, включая успех со второй попытки ping. Другие ответы внутри той же подсети не создают повторов. Учитывается история подтверждённых ответов: однажды ответившая сеть остаётся в этом списке. Конкретные IP и подробности попыток сохраняются в JSONL и HTML. При продолжении старого запуска или запуске `export_results.py` прежний `reachable-ips.txt` заменяется на `reachable-cidrs.txt`; исходные JSONL-журналы остаются источником подтверждения.

### Папка grouped: результаты в JSONL

После завершения сканирования, остановки через `Ctrl+C` и продолжения через `--resume` внутри каталога запуска автоматически создаётся или обновляется папка **`grouped`**. Все файлы в ней имеют формат JSONL: одна JSON-запись на строку. Пустые категории тоже создаются.

| Файл | Содержимое |
| --- | --- |
| `reachable-ips.jsonl` | Все успешные IP, включая ответившие со второй попытки |
| `errors-ips.jsonl` | IP с итоговой ошибкой проверки |
| `unreachable-ips.jsonl` | Проверенные IP, от которых ответ не получен |
| `networks.jsonl` | Все исходные сети с результатом каждого выбранного IP и количеством непроверенных образцов |
| `all-replied-networks.jsonl` | Сети, у которых ответили все выбранные образцы |
| `partial-networks.jsonl` | Все полностью обработанные выборки, где ответила только часть IP; при обычной выборке из трёх — один или два IP |
| `incomplete-networks.jsonl` | Сети с ещё не проверенными образцами; сюда входят и совсем не начатые сети |
| `summary.jsonl` | Одна запись со сводкой и количеством записей в каждом файле |

**Первый, средний и последний — позиции IP в выборке подсети, а не номера повторных попыток ping.** По умолчанию это три образца. Для одного образца используется позиция `single`, для двух — `first` и `last`. При расширенной выборке точный индекс каждого образца указан в `sample_index`, начиная с нуля; внутренние образцы обозначены `intermediate`, а единственный центральный при нечётном размере — `middle`.

В записи сети есть `responding_positions` и `samples` с подробностями всех образцов. Все частичные ответы объединены в одном файле `partial-networks.jsonl`: каждая сеть записана один раз, независимо от того, ответил первый, средний, последний IP или два из них. Например, при ответах первого и последнего IP поле `responding_positions` содержит `["first", "last"]`. Отдельные файлы по позициям больше не создаются; при пересборке старые `partial-first.jsonl`, `partial-middle.jsonl` и `partial-last.jsonl` удаляются после подготовки нового снимка. Сеть с непроверенными образцами попадает в `incomplete-networks.jsonl`, даже если один IP уже ответил; отсутствие результата не считается отсутствием ответа.

Группировка использует последний результат каждого `(CIDR, IP)`: если при продолжении старая ошибка исправлена успешной проверкой, этот IP исчезнет из нового `errors-ips.jsonl` и появится в `reachable-ips.jsonl`. Исходные `results.jsonl` и `errors.jsonl` сохраняют историю. Ошибки строк входного списка остаются в исходном `errors.jsonl`: у них может не быть корректного IP.

Файлы группировки пересобираются после окончания текущего запуска, а не после каждого пакета. Результаты каждого завершённого IP во время работы по-прежнему сразу сохраняются в исходном журнале. При аварийном завершении папку можно пересобрать отдельной командой. `summary.jsonl` публикуется последним; его отсутствие означает, что публикация не закончена. У записей одного снимка совпадает `generation_id`.

Для уже существующих результатов, без повторного ping или TCP-проверок:

```bash
python3 export_results.py results/scan-EXAMPLE --input cidrs.txt
```

Нужен исходный список с тем же SHA-256, что в `manifest.json`. Если `--input` не указан, программа проверит путь из манифеста, затем поставляемый `cidrs.txt`. Команда не изменяет исходные журналы и отказывается запускаться, пока этот каталог занят активным сканированием. Незавершённая последняя JSON-строка при таком экспорте не учитывается и не исправляется; об этом выводится предупреждение.

### HTML-отчёт

Одновременно с папкой `grouped` программа автоматически создаёт **`report.html` в каталоге запуска**, рядом с `manifest.json`. Откройте его обычным браузером: сервер, интернет и дополнительные библиотеки не нужны. После завершения, остановки через `Ctrl+C` и продолжения через `--resume` отчёт обновляется. Команда `export_results.py` также формирует HTML для старого журнала без повторного сканирования.

В отчёте есть сводка по IP и процент выполнения, поиск IP/CIDR, фильтры сетей, сортировка, выбор числа строк и страницы. Частичные ответы одного или двух из трёх образцов показаны одной категорией. Незавершённые сети отделены от неответивших. Раскройте сеть, чтобы увидеть позиции выбранных IP, каждую попытку ping, причины, время проверки с годом и длительность выполнения команды. Длительность команды не является чистым сетевым RTT.

В категории **«Частичный ответ»** появляется дополнительный фильтр по ответившим образцам: **первый, средний и последний IP**. Можно выбрать несколько позиций. Режим **«Хотя бы один выбранный»** показывает сети, где ответила любая из отмеченных позиций; **«Точное сочетание»** требует совпадения всех ответивших позиций с выбором. Например, первый + последний в точном режиме показывают только сети с этими двумя ответами. Если позиции не выбраны, отображаются все частичные ответы. Галочка **«Искать только среди ответивших IP»** ограничивает основной поиск успешными IP, сохраняя поиск по CIDR. Кнопка **«Сбросить фильтр ответов»** очищает дополнительные условия, сохраняя строку поиска. В других категориях эти условия не применяются. Это фильтр просмотра HTML; JSONL продолжает содержать единый полный список частичных ответов.

Все данные находятся внутри самого HTML-файла. На странице одновременно отображается только выбранная порция сетей. Дата и время показаны в часовом поясе браузера. Данные из журнала отображаются как текст; отчёт не запускает проверки и не обращается к IP из списка.

Статусы в отчёте разделены:

| Статус | Значение |
|---|---|
| `reachable` | Проверяемый IP ответил выбранным способом |
| `unreachable` | Проверка выполнена, но положительного ответа нет |
| `error` | Измерение не удалось выполнить или распознать |

Отсутствие `ping`, ошибка запуска процесса и его аварийное завершение не превращают весь список в «недоступные IP». Доступность команды проверяется перед сетевым запуском. Проверки имеют ограниченное время выполнения; потоков и задач в очереди также ограниченное число.

## Продолжение

```powershell
python real-check-avaibility.py --resume results\scan-EXAMPLE
```

Укажите настоящий каталог предыдущего запуска вместо `scan-EXAMPLE`. Путь входного файла и не указанные в командной строке параметры измерений автоматически берутся из манифеста. Повторять прежние `--protocol`, `--port`, `--timeout`, `--attempts`, `--samples` и `--source-label` не требуется.

Содержимое исходного файла и параметры измерений должны совпадать с сохранённым манифестом. Если файл перемещён, можно задать новый `--input` с тем же содержимым. Явное изменение протокола, порта TCP, тайм-аута, числа попыток, выборки или подписи источника отклоняется; для другого измерения создайте новый запуск. Количество потоков и частоту запросов можно менять. Если их не задать, используются обычные значения `--workers 16 --rate 20`.

Ранее завершённые результаты `reachable` и `unreachable` пропускаются. Записи `error` и незавершённые IP проверяются снова. Результаты дописываются, а не стираются.

При `Ctrl+C` сохраняются уже завершённые записи и отменяются задачи, которые ещё не начали выполняться. Активные попытки завершаются в пределах своих тайм-аутов. После остановки можно использовать `--resume`.

Коды завершения: `0` — запуск завершён без ошибок измерений и ввода; `1` — ошибка настроек, ввода или измерений; `130` — остановка пользователем. Статус `unreachable` сам по себе не означает сбой программы.

## Что означает источник проверки

`--source-label` — только введённая вами подпись. Программа не определяет оператора связи и не переключает сетевые интерфейсы. Проверка идёт через текущую маршрутизацию компьютера, включая используемый VPN или другое соединение.

ICMP проверяет ответы на ping. TCP проверяет установление соединения с заданным портом; это не проверка TLS, HTTP или работы приложения. Ни один из этих режимов сам по себе не подтверждает включение IP в мобильный белый список.

## Проверки кода

```powershell
python -m unittest discover -s tests -v
```

Тесты используют временные каталоги и подменённые сетевые ответы: реальный массовый ping и обращения к внешним адресам не выполняются. Проверяются `/31` и `/32`, выбор адресов, сохранение и продолжение, разделение ошибок и недоступности, ограничение запросов, корректность команд проверки, оценка оставшегося времени и подсчёт прогресса при повторах, остановке и возобновлении.

## Источник списка RU

В `cidrs.txt` включён обычный список [IPdeny RU IPv4](https://www.ipdeny.com/ipblocks/data/countries/ru.zone), снимок от **4 ноября 2026 года**: **11 482 подсети**, охватывающие **45 245 248 адресов**. Все записи проверены как канонические публичные IPv4 CIDR; повторов и пересечений нет. Дополнительное объединение соседних сетей не выполнялось, чтобы сохранять границы выборки адресов.

Дата источника, время загрузки и SHA-256 записаны в `cidrs.source.json`. Уведомление IPdeny сохранено без изменений в `Copyrights.txt` и входит в архив. Сведения о стране относятся к классификации источника по регистрации/распределению ресурсов; это не гарантия физического расположения адреса и не список проверенных доступных IP.

При замене входного списка меняется его отпечаток. Для нового списка создаётся новый запуск; продолжение прежнего журнала требует прежнего содержимого входного файла.
